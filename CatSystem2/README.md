# CatScene (.cst) 无损反汇编与文本回封工具

CS2 / CatScene 引擎脚本的全量反汇编、双行文本提取、变长回封。
纯标准库 Python 3.11+，无第三方依赖（拖放可选装 `windnd`）。

## 快速开始

不懂逆向就双击 `run_gui.py`，三个按钮从上到下点完：

```
①  全 量 反 汇 编      ← 拖入 .cst 或文件夹后点这个
②  提 取 双 行 文 本    ← ① 的逐字节校验通过才会亮
③  回 封 文 本          ← 改完 texts/ 里的译文回来点这个
```

② 和 ③ 之间用任意编辑器改 `output/texts/*.txt`，**只改 `●` 开头那一行**。
③ 的产物在 `output/rebuilt/`，文件名与原文一致，复制回游戏目录覆盖即可。
原始文件全程不会被修改。

## 命令行

```bash
# 全量反汇编（IR + asm + 双行文本 + 覆盖证书）
python disassembler.py <文件或目录> [-o 输出目录] [--jobs N] [--no-asm] [--key key.dat]

# 回封（12 条导入校验 → 策略协商 → 站点同构验证）
python assembler.py <texts 目录> [--strategy pointer-rewrite] [--source-root 原始目录]

# 只解封装/重封装，不碰文本
python unpack.py <文件或目录> [-o 输出目录] [--key key.dat]
python unpack.py <裸载荷目录> --repack

# 验证
python tests.py <语料目录>                    # 32 个用例（§9 零突变验证）
python run_gates.py <输出目录> [--rebuilt 回封目录]   # 技能自带的四个门禁脚本
```

三个入口（拖放 / 命令行 / GUI）产出完全一致的 IR、产物与证书哈希。

## 格式概要

```
.cst = CatScene 头(16) + zlib 流
       └ 载荷 = 载荷头(16) + 块表 + 偏移表 + 记录流
                记录 = 01 <type> <payload…> 00
```

四个记录类型（980 个样本穷举，无未知取值）：

| type | 含义 | 处置 |
|---|---|---|
| `0x30` | 明文命令行（`cg 0 blend 0`） | `frozen`，但块内 `fselect` 选项与 `str` 标题会被切出可译段 |
| `0x20` | 对白 / 旁白 | `translatable`；零长度的是「清空文本框」标记，不导出 |
| `0x21` | 说话者名 | `translatable` |
| `0x02` | 页结束，payload 恒空 | 结构记录 |
| `0x03` | 第二种页结束（Yukikoi Melt 出现） | 结构记录 |

## `.cstl` 多语言层

第二部作品（Yukikoi Melt）除 `.cst` 外还有 `.cstl`：同名脚本的多语言文本覆盖层，
不压缩不加密、UTF-8。工具自动识别并按同一套流程处理。

```
CSTL + 4 零字节 + 语言数(u8) + 每语言(len + ASCII 名) + varint 条目数
     + 条目数 × 语言数 × (说话者, 正文)
```

**长度与计数用 0xFF 累加式变长整数，不是 LEB128**：`value=0; while b==0xFF: value+=255; value+=b`。
所以 `ff ff 17` = 255+255+23 = 533。按 LEB128 或 u8 读都会错位——这是本格式最大的坑。

条目单位是**页**而不是消息记录：条目数恒等于同名 `.cst` 里 `0x02`+`0x03` 的条数
（18/18 文件精确相符）。拿 `0x20` 的条数去对永远差一截。日文说话者槽与 `.cst` 的
`0x21` 记录 4050/4050 逐条相同，这是两者描述同一批对话的独立证据。

CatScene **不是字节码 VM**——命令是运行时按空格切词的明文。详见 `vm_analysis.md`。

`scene/` 是同一批脚本的**官方中文译本**，记录逐条对应。把它的 45,506 条译文当作

## 两个容易踩的坑

**不要重新压缩已解出的载荷。** 日文版 196 个文件的 zlib 流等于 `compress(payload, 9)`，
但中文版 171 个 `78 01` 文件穷举 level 1-9 × memLevel 1-9 × 5 种 strategy 都复现不出——
它们是另一个 deflate 实现压的。因此 `repack()` 在载荷哈希未变时**原样复用原始流**。
这一条把往返一致率从 809/980 提到 980/980。

**不要按值改写偏移。** 块表的 `first_record` 字段值域与记录偏移重叠，按值匹配会静默
破坏块表，且哈希与区间覆盖都检不出来。改写一律按站点（`join_sites` 的 `site_offset`）。
实测 `preserved_value_collisions = 21`——这个数不为零是正常的。

## 已知限制

- 命令参数语义未逐条逆向（`attr_def 401 402 403 404 405` 五个数的含义未确认），
  这是申报 T2 而非 T3 的原因。
- `[漢字/かんじ]` 注音未拆成独立 `ruby` 条目，作为正文一部分导出。
- 跨样本验证覆盖**两部作品**：イノセントガール（5 个来源 980 个文件）与
  Yukikoi Melt（73 个 `.cst` + 19 个 `.cstl`）。形态签名分布确实不同——
  后者多了 `0x03` 记录类型，这正是 §0.3 要求跨样本验证的理由。
  `tests.py` 内置形态签名统计，拿到新样本请先跑 `tests.py <新目录>`。
- **加密变体未验证**：本作 980 个文件全为明文。`opcodelist.CIPHER_PROBES` 提供了
  证据门控的探测框架（接受条件是「合法 zlib + 长度相符 + 载荷头自洽」三条硬约束），
  但没有加密样本可验，`confidence` 如实标 `unresolved`。遇到加密文件用 `--key` 指定密钥。
