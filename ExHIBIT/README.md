# ExHIBIT RLD 翻译工具

Guardian☆Place 等 ExHIBIT 引擎游戏的脚本文本导出／回封工具。

**不需要启动游戏，不需要注入 DLL，不需要 key.bin。** 密钥直接从 rld 文件本身
静态恢复。

## 用法

图形界面（双击即可）：

```
python run_gui.py
```

把游戏的 `rld` 文件夹拖进窗口，点「输出文本」，翻译产出的 `.txt`，
再点「回封文本」，最后把输出目录里的 `.rld` 复制回游戏的 `rld` 文件夹。

命令行：

```bash
# 导出（--asm 可同时出 ASM 清单，改逻辑用）
python disassembler.py "游戏\rld" -o "游戏\rld_text"

# 回封（译文改成中文时用 gb18030）
python assembler.py "游戏\rld" -t "游戏\rld_text" -o "游戏\rld_rebuilt" \
       --target-encoding gb18030

# 回封前预览，不写文件
python assembler.py "游戏\rld" -t "游戏\rld_text" -o "out" --dry-run
```

## 译文文件格式

```
# idx=00000029 off=0x00000C35 tag=name
○00000029○name○メイドさん
●00000029●name●女仆小姐

# idx=00000030 off=0x00000C40 tag=msg speaker=メイドさん
○00000030○msg○なんという暴言。
●00000030●msg●好过分的话。
```

- **只改 `●` 开头的行。** `○` 行是校验锚,改了会被拒绝。

### 人名怎么改

**每句台词前面都有一条 `tag=name` 行,直接改它就行。** 注释里的 `speaker=`
只是给你看的,不用管。

人名有两条路径,效果不同,按需选:

| 改哪里 | 效果 | 适合 |
|---|---|---|
| `defChara.rld.txt` 的 44 条 | 该角色**全部**台词一次生效,文件长度不变 | 统一改名 |
| 剧本里的逐行 `name` 行 | 只影响那一行 | 同一角色在不同场景要显示不同称呼 |

两条可以混用。逐行的 `name` 行**不改就不会写进文件**,人名表查表逻辑原样保留,
所以不用担心"没动过的行被改坏"。

截图里 `メイドさん`(蒼衣自称女仆时)和 `勇気`(人名表)在译文文件里格式完全一样,
你不需要区分哪个是特殊情况。
- 译文行导出时预填原文,所以随时可以只翻一半就回封,未翻的显示原文。
- `{{0A}}` 这种是无法显示的字节,不要删改。
- 标了 `frozen` 的条目(如字体名)照常导出但不可改动。

## 改人名会让立绘消失吗

不会。

`defChara.rld` 里除了人名表,还有 **263 条立绘定义行**,按"角色+表情+差分"
逐条定义 —— 哪条被写坏,就只有用到它的那几个表情消失,其他表情正常,
这就是"有的角色立绘时有时无"这类现象的成因。

本工具的加密词数按只截顶规则计算,263 条立绘行全部正确解密并原样写回。
实测改 5 个人名后立绘行**逐字节未变**,可以放心改名。

若手里的 `defChara.rld` 已有立绘行损坏(显示为乱码),无法就地修复 ——
密钥错误状态下写回会造成不可逆的信息丢失,必须从游戏原盘重新提取一份。


## 相对早期版本的改进

1. **人名表不再解坏。** 加密词数按只截顶规则计算 —— 若按有符号回绕的
   `& 0xFFFF` 掩码计算,唯一超过 256 KB 的脚本恰是 `defChara.rld`(人名表,
   66102 词),全表 97% 会保持未解密状态。
2. **行内人名覆盖不再丢。** 619 条屏幕署名(如 `メイドさん`、`謎の声`)由
   对话 op 自带的覆盖串提供,与人名表是两条独立路径,两处都可翻译。
3. **不需要注入游戏进程**取密钥。
4. **变长回封**,译文可以比原文长。
5. **篡改译文文件**(改原文行、改 idx、删条目、用过时导出文件)一律拒绝并指出位置。

细节见 `vm_analysis.md`。
